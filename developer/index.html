Tech Stack

Core Framework

  • Kotlin
  • Jetpack Compose
  • Single Activity + ViewModels
  • Manual DI (AppContainer)

Design

  • Material 3 Expressive
  • MaterialKolor (seed color schemes)
  • Google Sans Flex
  • Material Symbols Rounded

Data & Storage

  • Room (SQLite), UUID ids
  • Money as Long cents
  • kotlinx.serialization (settings, backups)
  • JobScheduler (reminders, rates)

Scanning

  • ML Kit text recognition (bundled)
  • mi. Budget's own receipt parser
  • Gemini Nano (on supported phones)

Key Decisions

Plain Kotlin Core

domain/, the receipt parser and the brand matcher use no Android types, so they test fast and could move to Kotlin Multiplatform later.

UUID Ids

Records use UUID strings instead of auto-increment numbers, so exports from different phones merge without collisions and re-imports are recognised as duplicates.

Money in Cents

Every amount is a Long of cents: no floating-point drift. All formatting goes through domain/Money.kt.

Filtering in Memory

Filters run in Kotlin rather than dynamic SQL. For a personal budget it's instant, and a new filter is a few lines.

Brand Matching

assets/brands.json (about 950 merchants, banks and services, with aliases, colours and default categories) matches offline, handling noise like SQ *STARBUCKS #1234. Everyday words (Target, Ring) only match the whole name.

Receipt Rows

OCR often splits "TOTAL" and "23.45" into separate columns, so the parser rebuilds rows from text bounding boxes. There's always an editable review.

Backup Format

A .mibudgetdata file is a zip of data.json (versioned schemaVersion; ISO dates, cents, #AARRGGBB colours, each category's full path) plus receipts/. Any future iOS, desktop or web version can read it. allowBackup is off: data leaves the phone only when you export it.

Development Setup

Prerequisites

  • Android Studio (2025.1 or newer)
  • JDK 17+
  • A phone or emulator (Android 8.0+)
  • Node.js 20+ (only for this website)

Installation

git clone https://github.com/mi-app-hub/mi-budget.git
cd mi-budget
./gradlew :app:fetchBrandIcons   # optional: merchant logos (network, build time only)

Running the App

./gradlew :app:installDebug        # build + install mi. Budget dev beside the release
./gradlew :app:testDebugUnitTest   # run the logic tests

Debug builds install as mi. Budget dev, a separate app from the release, so they never touch your real data. Judge speed on a release build: debug Compose builds are much slower.

Core Concepts

The Main Bar

ui/common/MainBar.kt: Library · calendar · + · ⋮ · Settings. Swiping its Pill brings in the Library, Settings or Calendar as sheets that follow the finger (SheetHost.kt), and each sheet's search Pill morphs out of the bar's.

Settings

One @Serializable AppSettings (data/Settings.kt) saved as JSON, with Choice enums, sanitized() and migrated(). One file per section in ui/settings/; searchSettings() is pure and tested.

Storage Rules

Every file the app writes has one owner and is deleted when its owner is done: receipt photos with their purchase, camera captures once copied, unpacked backups after import. A launch sweep catches leftovers from crashes, touching only files older than the launch.

Making a Release

Bump appVersionName and appVersionCode at the top of app/build.gradle.kts, then fetch the bundled data and build:

./gradlew clean
./gradlew :app:fetchBrandIcons -Prefresh :app:fetchFxRates
./gradlew clean :app:assembleRelease :app:testDebugUnitTest
# → app/build/outputs/apk/release/mi-budget-<version>-release.apk

Signing: create a keystore.properties file in the project root (it is git-ignored) with storeFile, storePassword, keyAlias and keyPassword. Without it, release builds use this computer's debug key: fine for testing, not for publishing.

Publishing: tag the version, draft a GitHub release with the notes from docs/releases/ (full URLs only) and the APK attached, and add it to CHANGELOG.md. The website deploys separately: cd docs && npm run deploy builds it and publishes to the gh-pages branch.
